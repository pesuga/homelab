# Authentik External URL Configuration

## Current Issue

The Authentik ForwardAuth integration is redirecting users to the internal cluster DNS name instead of the public URL:
- Current: `http://authentik-server.authentik.svc.cluster.local:9000/application/o/authorize/...`
- Required: `https://auth.pesulabs.net/application/o/authorize/...`

## Infrastructure Configuration ✅ COMPLETED

The following Kubernetes configuration changes have been applied:

###1. Authentik Server & Worker Deployment (infrastructure/kubernetes/auth/authentik/authentik.yaml:142-143)
Added environment variable to both server and worker:
```yaml
- name: AUTHENTIK_BOOTSTRAP_HOST_URL
  value: "https://auth.pesulabs.net"
```

**Note**: This variable only affects initial bootstrap. Existing configurations must be updated through the UI.

### 2. Traefik Middleware (infrastructure/kubernetes/homelab/authentik-middleware.yaml)
Created middleware in homelab namespace to avoid namespace conflicts.

### 3. IngressRoute Configuration (infrastructure/kubernetes/family-assistant-admin/ingressroute.yaml)
Updated to reference local namespace middleware without namespace specification.

### 4. Proxy Outpost (infrastructure/kubernetes/auth/authentik/proxy-outpost.yaml)
Deployed dedicated proxy outpost with proper token configuration.

## Required UI Configuration ⚠️ PENDING

To fix the redirect URL issue, update the following in the Authentik Admin UI:

### Step 1: Update Brand Configuration

1. Navigate to **https://auth.pesulabs.net/if/admin**
2. Go to **System** → **Brands**
3. Click on **authentik-default** (or your brand name)
4. Update the **Domain** field from empty or `authentik-server.authentik.svc.cluster.local` to:
   ```
   auth.pesulabs.net
   ```
5. Click **Update** to save

### Step 2: Verify Provider Configuration

1. Go to **Applications** → **Providers**
2. Click on **Family Admin Provider**
3. Verify/Update these settings:
   - **External host**: `https://admin.fa.pesulabs.net`
   - **Mode**: Forward auth (single application)
   - **Authorization flow**: default-provider-authorization-implicit-consent

### Step 3: Restart Outposts (if needed)

If the configuration doesn't take effect immediately:

```bash
# Restart the proxy outpost to reload configuration
kubectl rollout restart deployment authentik-proxy -n authentik

# Wait for it to come back up
kubectl rollout status deployment authentik-proxy -n authentik
```

## Troubleshooting

### Still Getting Internal URL

If you still see the internal URL after updating the brand:
1. Check that the brand domain is saved correctly
2. Restart both Authentik server and proxy outpost
3. Clear browser cookies for both `admin.fa.pesulabs.net` and `auth.pesulabs.net`
4. Try in incognito/private browsing mode

### 200 OK Instead of 302 Redirect

If you get a 200 OK directly to the Family Admin panel:
1. Check that the Traefik middleware is applied correctly
2. Verify the proxy outpost is running and healthy
3. Check Traefik logs for middleware errors

### Commands

```bash
# Check proxy outpost status
kubectl get pods -n authentik -l app.kubernetes.io/name=authentik-proxy

# View proxy outpost logs
kubectl logs -n authentik -l app.kubernetes.io/name=authentik-proxy --tail=50

# Check Traefik middleware
kubectl get middleware -n homelab authentik -o yaml

# Restart proxy outpost
kubectl rollout restart deployment authentik-proxy -n authentik
```

## Background: Why This Is Required

Authentik stores its configuration in the PostgreSQL database, not in environment variables. The `AUTHENTIK_BOOTSTRAP_HOST_URL` only affects the initial setup. For existing installations, you must update the configuration through the Admin UI.

The redirect URL is generated by the Authentik provider configuration, which uses the brand's domain setting. This is why updating the brand domain in the UI is the key step to fixing the redirect URL.
